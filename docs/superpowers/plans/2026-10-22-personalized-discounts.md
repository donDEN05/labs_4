# Персонализированное управление скидками — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Выполнить пять лабораторных по теме ВКР в отдельных папках с минимальным кодом, воспроизводимыми экспериментами, отчётами и презентацией.

**Architecture:** Общие данные, временное разбиение и метрики находятся в `shared/`. Каждая лабораторная имеет один основной скрипт; вспомогательный файл создаётся только для самостоятельной, достаточно большой задачи. Историческая оценка прогнозов и симуляция эффекта скидок разделены.

**Tech Stack:** Python, NumPy, pandas, PyTorch, Transformers, matplotlib, Pillow, python-docx, python-pptx. `pyreadr` применяется только если исходные данные доступны исключительно в R-формате. Установка — в локальное окружение проекта, без изменения системного Python.

**Spec:** [Согласованная спецификация](../specs/2026-10-22-personalized-discounts-design.md).

## Global Constraints

- Код минималистичный: Python, функции, обычные CSV/JSON, готовые библиотеки.
- Без веб-приложения, микросервисов, собственного фреймворка агентов, базы данных и платных API.
- Логику разных алгоритмов нельзя заменять одним алгоритмом под разными названиями.
- Параметры и победители выбираются по validation; test открывается после фиксации решения.
- Метрики не выдумываются и не копируются из методички.
- Модели выполняются последовательно.
- У каждого оптимизатора минимум пять seed; MARL также использует пять seed.
- Исходные Word-файлы не изменяются.
- Реализация в `D:/labs`; Git-репозиторий и внешняя публикация не требуются для локального выполнения.
- Отдельные каталоги: `lab01_llm`, `lab02_multimodal`, `lab03_marl`, `lab04_optimization`, `lab05_defense`.
- Отчёты и подписи на русском языке; результаты не объявляются причинным эффектом для реального магазина.

## Review Focus

1. Недостаток истории и пограничная неделя: исключить объект до split и проверить отсутствие пересечения целевых недель с историей следующей части.
2. Невалидный JSON/вероятность LLM: сохранить ответ и ошибку, не подменять меткой; отдельно учитывать invalid rate.
3. Отсутствующая модальность: получить определённый прогноз с маской отсутствия, без NaN и доступа к будущему.
4. Перерасход бюджета и нулевая маржа: контроллер ограничивает действие; нарушения до и после него считаются отдельно.
5. Прерванный запуск: журнал сохраняет статус и конфигурацию, агрегатор не считает неполный результат успешным.

## Протокол ресурсов и литературы

Первый этап проверяет реально доступные CPU/GPU, память и загрузку моделей. Базовый ограниченный протокол: окно истории 4 недели, не более 200 покупателей, 8 наиболее частых категорий по train; train/validation/test по времени 60/20/20 с необходимым удалением пограничных окон. Покупатели дополнительного переноса не входят в обучение. Выборка фиксируется до сравнения; непокрытые группы и размер переноса указываются в паспорте.

Для LLM: до 150 validation и до 300 test объектов, идентичные для всех моделей; не менее одного объекта каждого доступного класса. Выборка не балансируется по test-меткам. Температура 0, до 64 выходных токенов, zero-shot и six-shot, две инструкции. Лимит контекста одинаковый и не превышает минимально поддерживаемый контекст кандидатов. Примеры few-shot только из train. Результаты основного и дополнительного набора не смешиваются.

Для компактных моделей и MARL: seed 11, 22, 33, 44, 55. В оптимизации общая сетка learning rate 0.0001, 0.001, 0.01; 300 шагов на конфигурацию, одинаковая архитектура и constant scheduler. Мультимодальность — 300 шагов обучения на схему и seed. MARL — 2000 шагов среды на алгоритм и seed; сетка гиперпараметров одинакового размера, обучение и выбор по отдельным эпизодам. Эти бюджеты обозначаются как ограниченные исследовательские эксперименты; недостаточная сходимость не скрывается. При необходимости корректировка бюджета делается до основного сравнения и записывается в config с причиной.

Для доверительных интервалов — 1000 bootstrap-повторов; для зависимости во времени — блоки недель. Для парного permutation test — 1000 перестановок и фиксированный seed. Уточняются единица ресэмплинга и множественные сравнения; отсутствие значимости не доказывает равенство.

По каждой из работ 1–4 отобрать 10–15 первичных источников с проверенными URL. В каждой строке матрицы: авторы, год, название, venue/статус, задача, метод, данные, split, метрики, код, ограничения, идея репликации, URL, дата проверки. Поисковые запросы, рассмотренные записи и причины исключения сохраняются, PRISMA-подобные числа получаются из этого журнала. В пятой работе — 25–40 уникальных релевантных источников из общего корпуса. При нехватке подходящих отечественных работ описывается реальная область поиска, а не выдумываются публикации.
